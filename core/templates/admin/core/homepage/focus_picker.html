{% comment %} Admin only: the front page's picture, whole, with the focal point drawn on it. ⚠️ `object-fit: contain` (in the stylesheet, not here) — the **entire** picture has to be visible while somebody is choosing a point inside it. Showing it cropped, the way the site shows it, would mean picking a point on a picture whose edges you cannot see, which is the problem this widget exists to solve. ⚠️ The two number inputs are **not** replaced by this. They stay in the form and keep working with JavaScript switched off; the script demotes them to a read-out once it has taken over. Hiding them from the stylesheet instead would hide them in the one case they are needed — when the script did not run. See D24's line on write paths. ⚠️ A video is previewed too, at `preload="metadata"` so it costs a frame rather than the whole file. The focal point applies to both, and a widget that only worked for one of them would read as broken on the day somebody swaps. ⚠️ **Both media tags are always rendered, and emptiness is `hidden` rather than an `{% templatetag openblock %} if {% templatetag closeblock %}` wrapped round the lot** (2026-08-13). The reason is the live preview: until then this markup only existed once a file had been *saved*, so choosing a picture and looking down at the framing tool showed the sentence "add a picture and save" — the tool turned up on the second visit to the page, and the framing could not be set in the same pass as the upload. The script swaps in the file the browser is already holding, and it can only do that if there is something in the document to swap it into. ⚠️ The two `data-*-url` attributes are what is **stored**, kept apart from what is merely *chosen* in the file inputs. Reading the saved URL back off `src` would not survive a preview being drawn over it, and "cancel the upload and the old picture is gone" is a widget lying about the state of the record. ⚠️ Still renders nothing that is submitted, and the script writes nothing of its own — including the admin's own "Clear" checkbox, which it reads and never sets. Somebody who ticks Clear *and* picks a file has contradicted themselves, Django refuses that on submit and says so, and a widget that quietly untangled it would be deciding which half they meant. {% endcomment %}
