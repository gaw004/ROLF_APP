或需要给外部用户看的页面时**" —— [零](../goal.md#零当前优先级2026-07-29-定)的 P3 恰好就是这句话，

**何时重新考虑**：需要做志愿者自助登录、或需要给外部用户看的页面时。

## 2026-07-31 复核：「不上 React」这一半再次确认

Phase C 开工前重新问了一遍这个问题（起因是"页面要好看"），结论**不变**，
但理由比 2026-07-29 那次更强了一条：

**分离想买的东西，这个项目已经买到了。** 分离的核心好处是「换前端时后端不用动」，
靠的是业务逻辑不在界面层 —— 而 [D18 的落点规矩](D18-admin-boundary.md#逻辑落点的硬规矩成本为零现在就要守)
已经强制了这件事，且有 12 条 grep 守卫在测试里盯着。
真要换 React 的那天，要写的只是一层 serializer。

**而分离要付的代价里最贵的一条，正好打在 [D20](D20-ministry-role.md) 上：
权限判断会变成两份。** 服务端那份是安全边界必须留，但前端还要再判断一次
才知道该不该显示按钮，而它够不到 `org/permissions.py`。
D20 存在的全部理由就是"散落的权限判断迟早有一处忘了 `.active()`，
而漏掉的权限检查是静默的"。

**顺带澄清一个混淆**：颜值和这个选择无关。**Tailwind 是 CSS，不是 React**，
服务端渲染照样用。Phase C 走的就是模板 + Tailwind，见
[`../phase-c.md`](../phase-c.md#考虑过并否决的全量-react-spa)。

**重启条件**（比原来更具体）：真的要做手机 App，或者真的有第二个人专职做前端时。
完整理由和代价清单在 [`../deferred.md`](../deferred.md)。
