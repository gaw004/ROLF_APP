# D3 · 数据永远是一个标准 `pg_dump` 能带走的 Postgres 库

> 本文件是 `../goal.md` 拆出来的一条决策记录（2026-07-30 拆分，内容一字未改）。
> **`goal.md` 仍是唯一入口**：决策一览表和「去哪找」都在那里，
> 代码注释里写的 `goal.md D3` 指的就是本文件。

这是"数据掌握在自己手里"的具体定义。应用可以换、平台可以换，数据不被绑架。
**推论**：不用平台专有的数据服务，不用需要特殊导出流程的存储。

## 2026-08-03 补：Render 的托管 Postgres 过不过这一关

**过。** Phase C 决定数据库也用 Render 的托管 Postgres
（见 [`../phase-c.md` 本轮定下的四件事](../phase-c.md#二本轮定下的四件事)），
这一条不构成偏离 —— 判据是一个能当场做的动作：

> 拿 `DATABASE_URL` 跑一次 `pg_dump`，**导出来的东西能不能灌进任何一台标准 Postgres**？

Render 给的就是一个标准 Postgres 的连接串，答案是能。
它和"平台专有的数据服务"（Firestore、DynamoDB、平台自己的 KV）的区别不在于谁托管，
**在于导出格式是不是通用的**。

⚠️ **但有一条真的会咬人**：如果**备份也放在 Render**，
那就是库和备份在同一家 —— 平台账号出事、误删、或者厂商本身出问题，两边一起没。
所以 Phase C 的备份存到 **Cloudflare R2**，不是 Render 自带的那份
（自带的那份留着当第二道，不当第一道）。
**这条决策真正兑现的地方是那个备份脚本**，见
[`../03-roadmap.md` 的 C3.6](../03-roadmap.md#c36-备份--恢复演练) ——
在它跑起来之前，"一个 `pg_dump` 就能带走"始终只是纸上承诺。
