# D30 · 注册与登录：邮箱即账号，Google 只用来预填，限流挡住的是脚本那一半（2026-08-07 起）

结论三条，彼此独立但同属注册这一段路：

1. **登录名就是邮箱地址**，没有单独的 username（`USERNAME_FIELD = "email"`）；
2. **Google 登录不是一种登录方式**，它只往注册表单里填三个格子，
   建出来的仍然是普通密码账号；
3. **注册页限流，两条同时生效**（每 IP + 全站），用 IP 的取法专门写了一个函数。

⚠️ 和 [D29](D29-memories-wall.md) 一样，这条也是**补写的**（2026-08-09）——
代码 2026-08-07 就在跑，只记在 [`revisions.md`](../revisions.md) 里。

## 一、邮箱即账号

⚠️ 连带后果写在这里，因为它每天都会撞到：`createsuperuser` 问的是**邮箱**，
不填不让过。README 的「跑起来」那一段已经照这个改了。

⚠️ 由此产生一个**真实存在的人进不来**的情况，而且是有意接受的：
`seed_demo` 里那位既没邮箱也没电话的志愿者，**没有登录账号** ——
账号就是一个邮箱地址，没有地址就没有账号。他仍然是一条完整的 Contact，
仍然能被报名、被记工时，只是不能自助。这是 [D12](D12-user-on-contact.md)
（User 挂在 Contact 上）本来就允许的形状，不是这一条新造的洞。

⚠️ `REQUIRED_FIELDS` 里**不许**再出现 email —— Django 的 `auth.E002` 会直接拒绝启动。
查表用 `__iexact`（`USERNAME_FIELD` 那条），存之前走 `normalize_email()`。

## 二、⭐ Google 那一段：它是预填，不是登录

这是本条里最容易被读反的一件事，所以写成不变量：

> 拿着一个 Google 账号，**在这个系统里什么都不代表**。
> 它给的是一个地址和一个名字，人照样自己设密码，建出来的是普通密码账号。
> 全仓没有任何一个分支因为这个 token 而信任任何东西 —— 除了三个文本框。

⚠️ 安全叙述之所以这么短，就是因为这一条：一个伪造的 token 能造成的最坏结果，
是**在一个马上要被它的持有者改掉的框里填了别人的名字**。仍然验签，是因为
一次调用就能让那三个框不成为可以注入任意字符串的地方。

⚠️ **故意不看 `email_verified`。** Google 会返回它，但照它行事等于对一部分账号
悄悄不填那个框 —— 而任何人本来就能手打任意地址进去，这个项目现阶段也不在注册时
验证地址（见 phase-c.md 已知缺口）。一个**不改变任何可能性**、只换来一个没人
解释得清的空框的检查，不值得有。

⚠️ HTTP 走 `urllib.request`，不引 `requests`。理由是依赖重量不是口味：
google-auth 自带的 transport 要 `requests`，而它拖着 urllib3 / certifi / idna /
charset-normalizer 四个。本项目已经有一处用标准库跟外部 provider 说话
（`core/notifications/novu.py`），这里跟的是**已经在的那个模式**，
而不是新起第二个。
⚠️ TLS 校验没有手写：`urlopen` 默认按系统信任库验，JWT 签名整个留在 google-auth 里。

## 三、限流：买到了什么，没买到什么

注册是这个站上**匿名陌生人唯一能做的写操作**，而且一次写**两行**（User + Contact，P1）。

| | |
|---|---|
| 挡得住 | 自动化那一半。脚本想要几千个号，**拿到二十个** |
| 挡不住 | 有人**手动**拿一个不属于自己的地址注册 |

⚠️ 挡不住的那一半需要「地址验证通过之后账号才生效」，而那需要真的能发信
（SES，C3.3）—— 所以是**推迟**，不是做一半。这个洞记进 phase-c.md 的已知缺口。

⚠️ 为什么这件事要紧：脚本灌进来的是**长得和真人一模一样**的 Contact 行。
而「人和组织共用一张表」是 [D4](D04-contact-one-table.md) 有意选的，撤不掉；
`merge_contacts()` 处理的是**重复**，不是垃圾。

### 两条限流，答的是两种攻击

`@ratelimit(key="ip", …)` + `@ratelimit(key=site_wide, …)`：
前者挡一台机器问一千次，后者挡一千台机器各问一次 —— **而后者是前者根本看不见的**。

两个速率都从环境变量读（`REGISTRATION_RATELIMIT_PER_IP` / `_SITE`），
默认 `20/h` 和 `100/h`，按请求读，于是被刷的时候不用重新部署就能改。

⚠️ `block=False`，不让装饰器自己抛 —— 抛出来是一个和本站其它页面长得都不一样的
错误页。改成自己渲染 `registration_rate_limited.html`。

### 🔴 `client_ip()`：不写这个函数，线上会**静默地**量错东西

⚠️ 反向代理后面（Render 也是），`REMOTE_ADDR` 是代理 ——
于是**全世界的访客共用一个桶**：本小时头二十次注册把所有人的额度用光，
而且没有任何东西会报告「这个限流量的是错的东西」。

⚠️ 而**顺手的修法比这个 bug 更糟**：整个信任 `X-Forwarded-For`，
调用方就能每次请求编一个新的客户端地址 —— 那是「戴着限流器的无限注册」。
这个头是一个每一跳都**往后追加**的列表，所以能信的是**最后**那一项
（我们自己的代理加的），永远不是第一项（调用方打的字）。

⚠️ 所以做成一个开关，**默认关**：开发机、以及任何前面没有代理的部署，
数 `REMOTE_ADDR` 是对的。真有代理的那个部署必须**主动**打开它。

⚠️ django-ratelimit 数在 cache 里，而 Django 默认的 cache 是**每进程内存** ——
多个 worker 各数各的，等于限额乘以 worker 数。所以有
`core/migrations/0004_cache_table.py`：计数落到数据库表里。
