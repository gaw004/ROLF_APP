# D38 · 身份轴：这一次参与是「志愿服务」还是「工作安排」（2026-08-14）

结论：`Participation` 加一个字段 **`served_as`**（`volunteer` / `work`），
外加一个记「这句话是谁说的」的 **`served_as_declared_by`**（`self` / `admin`）。
默认值由在编状态推出来，但**永远显示、永远可改、改动留痕**，
而**说这句话的人首先是当事人自己**。

> ⚠️ 本条落地时**取消了** [D35](D35-event-assignment-path.md) 原计划的
> `Participation.source`（`self_signup` / `assigned`）—— 那个字段是这个身份轴的
> 代理变量，真事实一记下来它就没有读者了。理由见第一节末尾。

起因是基金会的第二批需求里那两句：

> 员工可以很清楚地 tell，哪些是他自愿作为 volunteer 做的爱心活动，
> 哪些是工作安排而参加的 event 活动。
>
> 基金会需要能很清楚地 tell，哪些人（虽然也是员工）做的有些活动是出于自己的爱心，
> 哪些人他做的事看似是献爱心的 event，但实际上是工作。

同一句话问了两遍，一遍从人的角度、一遍从机构的角度 —— 这是同一个事实要被两侧读到，
所以它必须是**存下来的一个字段**，不是任何一侧的页面自己去推。

## ⭐ 唯一的不变量：这个事实只由一个字段承载，且它不是从别的字段推出来的

**`Participation.served_as`。** R6 / R7 的「志愿者工时」、R8 名单上的身份列、
My Schedule 的两条泳道、FLSA 提示、年报里那个可印的志愿小时数 —— 全都读它。

⚠️ 这一条排除掉的是本轮最容易走的那条歪路：**用别的字段推**。
下面第二、三节各否决一个推法，它们看起来都很像对的，而且都不报错。

## 一、为什么它不能靠「怎么进来的」推出来

「这一行是怎么进来的」（谁点了那个按钮）和「他是以什么身份来的」是两件事。
四种组合全都真实存在：

| | 自己报的名 | admin 放进去的 |
|---|---|---|
| `served_as=volunteer` | 员工自己报名周末募捐 —— 最典型的献爱心 | admin 拿着纸质名单，替一个自己来帮忙的员工录入 |
| `served_as=work` | 主管说了「你去把发放日报上」—— 按钮是他自己点的，但这是工作 | admin 直接把他排进这场活动 |

对角线那两格正是基金会问的那两句话所指的人。
拿"怎么进来的"当身份用，这两格会静默算错 ——
「谁点的按钮」和「这算不算工作」**没有因果关系**，只是相关。
这是 [D32](D32-worker-axes-schedule-and-assignment.md) 判过一次的同一个病
（一个字段扛两个轴），只是这次两个轴长得更像。

### 于是 `source` 这个字段被取消了

[D35](D35-event-assignment-path.md) 原计划加一个 `Participation.source`
（`self_signup` / `assigned`）。它当初唯一的用处就是**当这个身份轴的代理变量** ——
真事实一旦被直接记下来，它就没有读者了；它剩下的那件事（这一行是谁造的）
simple-history 的创建行答得更细。

⚠️ 而留着它有代价：两个字段会在同一次迁移落地、出现在同一个表单上、
名字都很短、值还都是「自己 / 别人」——**下一个人一定会把它们合并成一个，
而合并之后错的是承重的那一个。** 全文见 [D35 第二节](D35-event-assignment-path.md)。

**真正要保住的那半件事**（这句身份是谁说的）挂在事实上，不挂在行上 ——
`served_as_declared_by`，见第四节。

## 二、为什么不用「在本 ministry 有带薪编制」推 —— 推翻原来的排除规则

本轮之前定的口径是：R6 / R7 排除「在办这场活动的那个 ministry 里持有 `paid` / `stipend` 编制的人」。
那是一个**代理变量**，两头都错：

| 实际情况 | 代理变量给出的答案 |
|---|---|
| 食物银行的带薪协调员，周末来做募捐晚宴的接待（真志愿） | 算成工作，从「志愿者工时」里删掉 |
| 财务部的带薪员工被派去食物银行支援发放日（真工作） | 算成志愿，混进「志愿者工时」 |

⚠️ 而第一行还有一个更糟的后果：**那几个小时会从两个账本里同时消失。**
`Participation` 那一边被排除规则删掉，`Shift` 那一边根本没有行（周末不是他的排班）。
系统里从此不存在这段时间，且不报错 —— 这和 [D27](D27-ministry-report.md) 立的那条
「没有和没算不能长得一样」正好反过来：它把「有、但不该算进这个数」做成了「没有」。

**FLSA 的四条判据问的恰恰是身份**：是否真自愿、是否出于公益 / 慈善 / 人道动机、
是否不期待报酬、**是否不是他受雇从事的同类工作**。没有一条问「哪个部门」。
所以记下身份不是多加一个字段，是把法律真正要的那个事实**第一次记下来**；
而 ministry 那个代理变量，从来就不是法律问的问题。

**排除规则整个删掉。** R6 / R7 换成一个 filter（`served_as=volunteer`），
三条规则、跨 ministry 的例外、`stipend` 归堆——全部消失。
这是本轮唯一一处**又更准、又更少代码**的改动。

## 三、为什么不用「他那天有没有排班」推

听起来很干净：活动时段落在他的 `Shift` 里 → 工作，否则 → 志愿。它错在两头：

- 无薪在编人员**大部分没有班表**（[D36](D36-two-hour-ledgers.md) 的 `hours_tracking` 就是为这批人建的），
  于是所有人都被推成志愿，包括真的被安排去干活的；
- 带薪员工被安排在**周六**去办一场活动，那天没有排班行，同样被推成志愿。

推不出来的根本原因是：**排班表答的是「他这段时间在不在岗」，不是「他为什么去」。**
后者只有人知道。

⚠️ 但这个判断有另一个用处，见第七节：它不是身份的**来源**，是身份的**校验**。

## 四、谁来说这句话：本人声明，admin 可更正，改动留痕

这是本条决策里唯一一处不能省的复杂度。

**首先是当事人自己。** FLSA 要求志愿必须是 genuinely voluntary，
而**当事人自己的声明才是那份证据**。雇主替雇员宣布「这段时间他是无偿志愿的」
恰恰是执法机关最先怀疑的形状 —— 让 admin 单方面勾这个框，
等于把系统做成一份自己给自己开的证明。

落地成三句话：

1. **自己报名** → 报名表单上一个问题，两个选项，带默认值；
2. **被指派** → 邀请里带同一个问题，**接受的时候答**（他本来就要点一下接受，不多一次操作）；
3. **admin 可以更正**，更正走 simple-history，**且本人在 My Schedule 上看得见当前值**。

⚠️ **Django admin 是一条不写代码就存在的第四条路径。**
`events/admin.py::ParticipationAdmin` 现在是可编辑的，
而「只有一处写 `served_as`」那条守卫 grep 的是代码里的赋值 ——
**admin 表单它一个字也拦不住**。后果不是改错值，是
**改了值而 `declared_by` 是空的**：报表把它当成「身份未记录」，
FLSA 提示读不到"这句话是谁说的"，而页面上看起来一切正常。

**处置**：`served_as` / `served_as_declared_by` 在 `ParticipationAdmin` 里 `readonly`，
更正只能走页面上那个动作（它调 `set_served_as()`）。
`checked_in_method` 本来就该是同样待遇 —— 同一条规矩用在第二个事实上。

### `served_as_declared_by`：这句话是谁说的，本身要记下来

```python
served_as_declared_by = self | admin      # 每次写 served_as 时一起写
```

三个用处，每一个单独都不够，合起来够：

1. ⚠️ **证据价值全在这一格里。** 一个带薪员工的「志愿」如果是 admin 替他勾的，
   那正是第二节说的、执法机关最先怀疑的形状 —— 而只看 `served_as` 分辨不出来。
   [D36](D36-two-hour-ledgers.md) 的 FLSA 提示读它；
2. **本人看得见有没有人动过**：My Schedule 上那一行写「你自己填的」
   或「由 Food Pantry 的管理员设置」。下面那条 🔴 因此有了具体落点 ——
   「看得见」不再是一句原则，是页面上的一行字；
3. 它答得出旧的 `source` 答不出的那一格：**自己报的名、事后被 admin 改成了工作安排**。

形状照 `Participation.checked_in_method`（「这一行的考勤是他填的还是我填的」）——
不是新规矩，是同一条规矩用在第二个事实上。
⚠️ 同样**没有 `default`**：空值只可能来自第九节那次回填。

### 分歧时谁说了算

以 admin 为准 —— R6 / R7 和 FLSA 提示是机构要对外负责的数字。
**但「看得见」不可交易**：一个人不应该在不知情的情况下，
被把自己捐出去的一个周末改写成上班。这一条是本决策里唯一的 🔴：

> 🔴 **不要做「admin 静默批量改身份」的入口。** 一次改一行、留痕、本人看得见。
> 批量按钮会让这个字段在一次点击里失去全部证据价值。

**不做审批流。** 一个要人审批的字段，在一个五十人的基金会里的实际表现是
「大部分停在待审批」—— 同 [D32](D32-worker-axes-schedule-and-assignment.md)
那条「让人每次点接受，两周之内就没人点了」。

## 五、默认值：让 95% 的人根本不需要想这件事

| 谁 | 默认 | 那个问题出不出现 |
|---|---|---|
| 没有在编身份的人（外部志愿者） | `volunteer` | 完全不出现 |
| **理事**（`kind=board`） | `volunteer` | **完全不出现**，见下 |
| 在编 `staff` + 自己报名 | `volunteer`（自己去的，推定是爱心） | 出现 |
| 在编 `staff` + 被 admin 指派 | `work`（被安排的，推定是工作） | 出现 |

第一行是这套设计里最要紧的一格：**绝大多数报名的人是外部志愿者，他们一个字都不会多看到。**
易用性的代价只落在真的有这个歧义的那批人身上，而对他们来说这一问是有意义的。

⚠️ **理事那一行不能漏。** 判断"有没有在编身份"如果只问"有没有在职 `Assignment`"，
理事会被问到「志愿服务 / 工作安排」—— 而对一个无薪理事来说
「工作安排」这一档没有意义（他不是雇员，FLSA 上也不是），
问了只会让他觉得这个系统不认识他。**只对 `kind=staff` 提问。**
这正是这一节自己的逻辑：把成本只压在真有歧义的人身上。

### ⚠️ 「有没有在编身份」按**活动那一天**判断，而且和显不显示是同一处

```python
events/services.py::default_served_as(contact, event) -> (value, ask)
    # ask=False = 这个人在这场活动上根本不该被问这个问题
```

> ### 2026-08-20 更正：返回的是一对，不是「值或 None」
>
> 本节原来写的签名是 `-> str | None`，`None` 表示「不该问」。实现时发现那个形状
> 和**上面这张表自相矛盾** —— 表的第一行同时说了两件事：外部志愿者默认
> `volunteer`，**而且**问题完全不出现。用 `None` 表示「不问」，就把这批人的
> 值一起丢了，而他们是志愿者工时那个数的绝大部分（R6 的 filter 正是
> `served_as=volunteer`），并且会比第九节回填出来的历史行还要空。
>
> 改成 `(value, ask)`。本节真正要的那一条 —— 「默认值是什么」和「问不问」
> 必须来自同一个函数 —— 一个字都没让步。
>
> 顺带定死一条口径：**不问的人照样落值，但 `served_as_declared_by` 留空。**
> 于是那一列的意思是「有人回答过这个问题」，和第九节回填
> 「一个字都不写 `declared_by`」是同一条线。

判断用 `Assignment.objects.active(on=活动日期)`，不是 `active()`。
按今天判断的表现是两个方向都错：去年离职的人今天报名**会**被问，
今天入职的人报一场去年的活动**不会**被问。
（同 [D32 第三节](D32-worker-axes-schedule-and-assignment.md) R8 那个 `on=` 的老坑，
第二次出现在同一个形状上。）

⚠️ **「默认值是什么」和「问不问」必须是同一个函数的返回值**，
不能表单自己判断一次、服务层再判断一次 ——
两处判断会在理事那一格、在离职那一天各走散一次，
而两次都是"表单没问、服务层写了个默认值"这种不报错的形状。

⚠️ **默认值必须显示出来，不能藏。** 藏起来的默认值等于替人做了声明，
第四节整节的理由就作废了。同 [D27](D27-ministry-report.md) 那条
「签到页的工时框有预填值」踩过的坑：预填出来的数字和人工确认过的数字长得一模一样。
这里的做法是**预选而不是预填** —— 选项两个都画出来，其中一个已选中。

## 六、措辞：这一条会决定人反不反感

同 [D32 第四节](D32-worker-axes-schedule-and-assignment.md) 那条「界面上不要管无薪的人叫 employee」，
一个成因：真出争议时，机构自己系统里的措辞就是对方的证据；而在此之前，
措辞决定了填这个框的人是什么心情。

> **2026-08-15 更正**：本行原来写的是「同 D32 第七节」——
> 而 D32 拆条之后只剩五节，那个指向落在一段不存在的内容上。
> 同一份文件第八节还有一处同样的错（指的是 [D33 第七节](D33-work-schedule.md)），一并改掉。
> 这正是 [`../goal.md`](../goal.md) 约定 3 说的假引用，
> 只不过它躲过了链接守卫 —— 守卫查的是文件和锚点，**查不到正文里的「第 N 节」**。

```
你这次以什么身份参加？
  ● 志愿服务 —— 我自己的时间
  ○ 工作安排 —— 算在我的工作时间里
```

三条规矩：

1. **不要用 duty / required / obligation 这类词**。被安排的那一档写「工作安排」，
   不写「职责要求」——后者会让本来就是来帮忙的人觉得自己在被审查；
2. **不要问「你这次拿不拿钱」。** 那个答案在 `Position.compensation` 里，
   问了既冒犯又不准（无薪在编人员两边都不拿钱，这个问法答不出任何东西）；
3. **两档都要是体面的。** 「工作安排」不是一个次等答案 —— 一个被派去主持发放日的员工，
   他那天的投入一点不比志愿者少，只是它进的是另一个账本。
   ⚠️ 页面上任何把 `volunteer` 那一档做得更醒目、更值得表扬的排版，
   都会把这个字段变成一个「大家都往那边填」的字段，两个数字同时失真。

### 措辞的唯一落点是本节（2026-08-15 补）

开工前的一次自查发现：**同一批标签，三份文档三种口径，而且一份都不是权威的。**

| 在哪 | 写的是什么 |
|---|---|
| [D23](D23-i18n-interface-only.md) | 界面统一写英文 |
| [D32 第四节](D32-worker-axes-schedule-and-assignment.md) | 无薪的人在界面上写 `Staff (unpaid)` / `Team member` |
| 本节 + [`../phase-d.md`](../phase-d.md) 的 My Schedule 原型图 | 「志愿服务」/「工作安排」（中文） |
| [`../goal.md`](../goal.md) 待定表第 5 条 | 「中文 / 英文措辞」列为待定 |

三份副本在**还没开工**的时候就已经存在了 —— 而本节自己刚说完措辞是承重的。
这个项目已经为「同一条规则的两份副本」付过三次学费，不要再付第四次。

**处置，三句话：**

1. **界面文案一律是英文**，这一条 [D23](D23-i18n-interface-only.md) 已经定过，不重开；
2. **本节是这两档措辞的唯一落点。** 文档别处（含 phase-d.md 的原型图）写的中文
   是**文档用语，不是 UI 文案** —— 那些地方要引本节，不许自己定一版；
3. ⚠️ **最终英文措辞还没定**（要和基金会一起过一遍，见 `goal.md` 待定表第 5 条），
   但**定下来之后写回这里**。工作默认值先用：

```
How were you serving this time?
  ● Volunteering — my own time
  ○ Scheduled work — counts as my work time
```

⚠️ 这两串**不许**先写进模板再回头改 —— 它出现在报名表单、邀请页、My Schedule
的每一行标签和 R8 名单的那一列上，改一次是四处。定不下来就先卡在这一节里。

### 字段为什么不叫 `capacity`

`capacity` 是 HR 的标准说法（acting in what capacity），但这是 `events` app ——
这里 capacity 会被读成「容量 / 还能报几个人」，而 `EventRole.needed_count` 和满员率就在隔壁。
`served_as` 没有这个歧义，代价只是它不是行话。

## 七、它让报表第一次答得出基金会那两个问题

### 员工侧（「我自己能 tell」）

My Schedule 一页、两条泳道，见 [`../phase-d.md`](../phase-d.md) 的页面表和 [D36](D36-two-hour-ledgers.md)。
要点在这里只说一句：**两条泳道永远并排，永远不求和，且每一行都带着自己那条泳道的标签**。

### 机构侧（「基金会能 tell」）

| 问题 | 靠什么答 |
|---|---|
| 某场活动里在编人员谁参与了、负责什么 —— **而且他是来上班的还是来献爱心的** | R8 名单加一列「身份」 |
| 志愿者一共做了多少工时（R6 / R7） | `served_as=volunteer` 一个 filter |
| 我们自己人额外贡献了多少 | 在编 + `served_as=volunteer` 的工时。⭐ 这是基金会最想知道、而在此之前**完全算不出来**的一个数 |
| 哪些「看着像献爱心」的其实是工作 | `served_as=work` 的那部分，按人和 ministry 分组 |

#### ⚠️ 第二、三行是**包含关系**，页面上不许画成三个平级的数

「我们自己人额外贡献」= 在编 + `volunteer`，它**是**「志愿者工时」的一个子集
（R6 的 filter 是 `served_as=volunteer`，**含在编人员**，第二节整节讲的就是
为什么不能把在编人员排除掉）。三个数并排画出来，第一反应就是加 ——
而这一轮花了整条 [D36](D36-two-hour-ledgers.md) 防的就是这件事。

**报表上写成**：

```
志愿者工时  1,240 小时（其中在编人员 180 小时）      身份未记录  36 小时
```

「身份未记录」是真正平级的第三个数（第九节那批回填留空的行），它必须画出来。

#### ⚠️ 换 filter 的落点是 `event_summary()`，不只是报表

R6 / R7 住在 `events/services.py::event_summary()` 里
（`total_hours` 和每个 role 的 `hours_total`），那个函数的注释还写着
"总数和分解从同一批行来，所以不会漂" —— **两处要在同一次改动里
一起加上 `filter=Q(served_as=volunteer)`**，否则它们当场就漂了。

而 D27 报表上那个 `hours`（「已记录工时」）**保持原义不动：
它是"这批活动一共记录了多少工时"，不分身份。**
理由：那个数和它旁边的 `hours_records` / `hours_missing` 是一组，
回答的是"这个总数建立在多少条记录上"（2026-08-05 定的那个偏差口径），
换成志愿口径会让分母和分子说的不是同一件事。
「志愿者工时」是它**旁边新加的一个数**，不是把它改掉。

### 那个可印的志愿小时数，现在有定义了

[D36](D36-two-hour-ledgers.md) 原来的结论是「没有一个总投入工时的数字可以印」。
对普通公司那句话没错，对非营利不成立 —— 那个数字是年报、董事会材料和 grant 申请里的标配
（Independent Sector 每年公布志愿小时的美元估值；IRS Form 990 Part I 第 6 行要报志愿者人数）。

有了身份轴之后它有了一个说得清的定义：

> **志愿服务小时数** =
> `served_as=volunteer` 的活动工时（**所有人**，含在编人员）
> ＋ `compensation=unpaid` 的在编人员的 `Shift` 实到工时

⚠️ 三条必须一起成立，少一条这个数就是错的：

1. **两个来源按定义不相交** —— `served_as=volunteer` 的意思就是「这不是我岗位职责的时间」，
   而 `Shift` 装的正是岗位职责时间。所以这一次**可以相加**，
   而 [D36](D36-two-hour-ledgers.md) 那条「两个账本永远不相加」**不撤销**：
   不许相加的是「工作投入」那两个数，这里加的是同一件事的两个来源；
2. `paid` / `stipend` 的 `Shift` 工时**永远不进这个数** —— 那是工资，不是捐赠的时间。
   ⚠️ `stipend` 这一档是**保守的政策口径，不是法律事实**，见
   [D32 第二节](D32-worker-axes-schedule-and-assignment.md)；
3. 相交了就是数据有问题（他在自己排班的时段里"志愿"做同一类工作），
   ⚠️ **而那正好是 FLSA 最该看的那个形状** → 出提示，见下。

#### ⚠️ 第二个来源会漏掉一批人，而漏掉的正是需求原文 ① 那批（2026-08-15 补）

上面那个口径的第二半读的是 `Shift`。而 [D33 第一节](D33-work-schedule.md) 明写：
`agreed` / `not_tracked` 的人**没有 `WorkPattern`，一行 `Shift` 都不生成**。

于是一个被标成 `agreed` 的无薪在编成员 —— 有固定岗位、机构对他的时间有承诺、
**正是需求原文 ① 说的那种「像员工的志愿者」** —— 他的小时数**一个都不进这个数**。

⚠️ 而它不报错：那个数看起来完全合理，只是系统性地偏低。
[D36 第三节](D36-two-hour-ledgers.md) 建「在编人员投入」那一块的理由，原话就是
「他们在志愿者工时上接近于零，而他们很可能是投入最多的一批」——
同一个病，报表内部那一半修好了，**要拿出去印的这一半没修**。

考虑过并否决的补法：把 `agreed` 的人按 `agreed_hours_per_week × 窗口周数` 折进去。
**不行** —— 那是把一个约定值和一批观测值求和，而
[D36 第四节](D36-two-hour-ledgers.md) 整节讲的就是这两种数不能混
（约定值那一格连**显示**都要带「约定值，非观测值」的注脚，更不该被加进一个要印出去的总数）。

处置：**口径一个字不动，改成把漏掉的人画出来**。

```
志愿服务小时数  1,240 小时（其中在编人员 180 小时）      身份未记录  36 小时

另有 4 位无薪在编成员按约定值或按产出考核，未计入上面这个数
```

这是 [D27](D27-ministry-report.md) 那条「没有和没算不能长得一样」的第三次应用
（前两次是未成年无同意记录、和「未确认」那第三个数）。
⚠️ 它比补数更贵一点的地方只有一处：**那行字必须一直在**，
哪怕某一年那个人数是 0 —— 人数为 0 和「没有这一类人」在页面上不能长得一样。

## 八、FLSA 提示：两条旧提示合成一条更准的，一处实现

| 触发条件 | 说什么 |
|---|---|
| `served_as=volunteer` + 当天在**该 ministry** 持 `paid` / `stipend` 编制 | 「这个人在本部门是带薪的。带薪员工不能以志愿者身份做他被雇来做的同一类工作 —— 请确认这次不是同类工作」 |
| `served_as=volunteer` + 活动时段落在他自己的 `Shift` 里 | ⚠️ 更硬的一条：「这段时间已经算作排班工作时间」——**同一段时间被记了两次，且身份互相矛盾** |

**都是提示，都不拦截** —— 代码判断不了「是不是同一类工作」，
这句话 [D33 第七节](D33-work-schedule.md) 已经写过一次，同一个成因。
两条合在一个函数里（`events/services.py::flsa_flags()`），因为它们要出现在同一处页面上。

### 2026-08-15 修订：第二条的触发条件放宽，而检测搬走了

第二条原来挂在 `served_as=volunteer` 上。**那让它漏掉了一半** ——
选了「工作安排」的那种重叠是**真正的分身乏术**（同一段时间他既要在岗位上、
又要在活动上），而它以前一句提示都没有。

处置（全文见 [D39 第四节](D39-scheduling-conflicts.md)）：

- **重叠的检测本身搬进 `org/services.py::conflicts_for()`**，两档都触发，
  而且它从事后的报表**挪到了做决定的那一刻**（报名页 · 指派页 · 代录页）；
- `flsa_flags()` 在那个结果上再加身份这一层，**两档两套措辞**：
  `volunteer` 那一档说的仍然是上表那句 FLSA 风险，
  `work` 那一档说的是「他已经排了班，一个人分不成两半」，那是排班冲突不是合规问题；
- 本表第一条（当天在该 ministry 持 `paid` / `stipend` 编制）**一个字不动** ——
  它不需要时间重叠，和 `conflicts_for()` 无关。

⚠️ 两档走**同一个检测、两套措辞**，不要写成两个检测 ——
那就是本项目判过三次的「同一条规则的两份副本」。

## 九、历史行怎么办 —— 🔴 不许 default 回填

`Participation` 已有的行没有身份。这里有一个看起来很方便、而且不报错的错：
给字段加 `default="volunteer"` 然后迁移一跑，所有旧行都成了志愿。

**那是替没有人核实过的事作证** —— 同 `Participation.checked_in_method`
那条已经写在模型里的规矩（「A default of ADMIN would back-date a claim onto every
historical row — vouching for something nobody checked」）。一模一样的形状，
所以这里照抄那条的处理：

| 旧行的情况 | 回填成 | 为什么 |
|---|---|---|
| 活动当天**没有**在职的 `kind=staff` 任职 | `volunteer` | 这不是假定，是**从数据里证得出来的**：他当时根本没有在编路径，不可能是工作安排 |
| 活动当天**有**在职的 `kind=staff` 任职 | 留空 | 这才是真的不知道 |

### 2026-08-19 收窄：判据里那半句 `kind=staff` 是后加的

上面这张表原来只说「有没有在职 `Assignment`」。那和第五节打架，
而打架的那一格是**理事**：第五节说理事根本不该被问这个问题（默认 `volunteer`、不问），
第九节按字面却会把他的旧行留空、送进「身份未记录」。
同一个人、同一件事，两节给两个答案。

收窄之后两处用的是**同一个判据**，而且只写一次 ——
回填的迁移 import `default_served_as()` 背后那个 queryset，不自己写一份：

> 活动那一天有没有在职的、`kind=staff` 的 `Assignment`（且岗位没有停用）。

⚠️ 这一条同时消掉了一个**将来才会发作**的分歧：判据要是抄成两份，
迟早有一份忘了理事、或者忘了 `on=活动那一天`，
而两边都不报错 —— 表现只是「身份未记录」那一格慢慢变大。

留空的那一批在报表上**单独占一格「身份未记录」**，不并进任何一边。
⚠️ 这一格现在很小（在编人员参加活动这件事在 Phase D 之前几乎没有路径 ——
[D35](D35-event-assignment-path.md) 说的就是这个），
所以它是一个便宜的诚实：一开始就画出来，比以后发现数字对不上再去追要便宜得多。

两个字段的形状因此都是 `CharField(choices=..., blank=True)`，**都没有 `default`**。
新行由 `services.py` 一律写值（三条默认规则在那里），
空值只可能来自这一次回填 —— 这句话要写进两个字段的注释里。

⚠️ 回填**不写 `served_as_declared_by`**，一个字都不写：那批行没有人声明过任何事，
写 `admin` 是在说"某个管理员判断过"，写 `self` 更糟。空就是空。

## 十、代价（如实记）

1. **在编的人报名时多回答一个问题。** 外部志愿者一个字没多；被指派的人也没多操作
   （问题挂在他本来就要点的「接受」上）。这是主动付的，换的是两侧都能 tell；
2. ⚠️ **`served_as` 靠人填、admin 能改，填错了不报错** —— 只是两个数字各错一点。
   缓解和 [D36](D36-two-hour-ledgers.md) 的 `hours_tracking` 完全一样：
   **显示在本人的 My Schedule 上和 R8 名单上**。一个只有 admin 看得见的身份字段，
   没有人会去维护它，也没有人会发现它错了；
3. **多一格「身份未记录」**（第九节）。它会一直存在，因为回填不许猜；
4. **两档之间的排版必须是中性的**（第六节第 3 条），而这是一条**没有测试盯得住**的规矩 ——
   它只能靠 review。写在这里是为了让它至少被读到一次。

## 十一、推迟的，以及各自的重启条件

| 事情 | 何时重新考虑 |
|---|---|
| 「这次算不算同一类工作」的结构化判断 | 真的出过一次 FLSA 争议时。⚠️ **别做成下拉框** —— 需要的是人的判断和一段说明，不是一个枚举 |
| 按身份分开的年度证书 / 表彰 | 基金会真的要发志愿服务证明时。那时 `served_as=volunteer` 的小时数就是证书上的那个数，字段已经在了 |
| 让本人事后自己改身份（现在只有 admin 能改） | 出现「我当时点错了」的真实抱怨时。⚠️ 那时要同时想清楚**活动结束多久之后不许再改** —— 否则它变成一个可以回头修改的证据 |
| `Shift` 上的身份 | **不需要**，而且要记住为什么：`Shift` 装的按定义就是岗位职责时间，
「这份岗位职责本身拿不拿钱」由 `Position.compensation` 答。两个轴不重叠，见第七节那个求和口径 |
