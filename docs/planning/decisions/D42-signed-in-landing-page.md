# D42 · `/me/` 是登录后的落脚点，落在一个没有模型的 app（2026-09-02）

结论：登录之后有一个地方回答「有什么在等我」—— 五张卡加一条侧栏，
落在新 app `dashboard`，URL `/me/`，`@login_required`。

它**不推翻** [D25](D25-public-front-page.md)，而是走在它划的线上：D25 否掉的是
「`/` 做成按角色分流的调度页」，理由是「把链接发给一个从没听过这个基金会的人，
他打开看到的是一张登录表单」，而它自己写着「那个调度器**有用**，但它不是首页」。
D25 同时留下了判据：

> 这一页是不是要发给一个还没有账号的人看的？是 → 公开。不是 → 要登录。

`/me/` 要登录，所以它不是 `/`。⚠️ `/` 一个字没改，**登录之后也不跳转** ——
那个跳转正是 D25 推翻掉的东西，而它是这一页存在之后最容易顺手加上的一行。
钉住它的是 `dashboard.tests.TheDashboardIsForOnePersonTests.test_it_does_not_replace_the_public_front_page`。

## ⭐ 唯一的不变量：每张卡必须过四条，不过就不建这张卡

1. 说得出**谁读它、读了之后会做什么**，一句话；
2. 内容**天然**不超过四行 —— 常常要截断的，那是一个页面，不是一张卡；
3. 有**唯一一条出口**，通向一个**已经存在**的页面，位置固定在卡底；
4. 有明确的空态，且空态不能和「加载失败」「你没权限」长得一样（[D27](D27-ministry-report.md)）。

这四条是整个仪表盘不烂掉的唯一保险。卡片这种形式**天然鼓励再加一张**，
而行业里这类页面的通病只有一句话：不要用五千个东西压垮你的受众。
门槛写死在这里，比「以后注意点」硬。

⚠️ 第 3 条还有一个不显然的后果：**出口必须通向已经存在的页面**。
一张卡如果需要一个新页面才说得完，那它要的其实是那个页面，不是一张卡。

## 一、为什么是一个新 app，而不是 `core`

第一版计划写的是「view 放 `core/views.py`」，和 `/` 做邻居。**那违反 D17。**

> [D17](D17-app-layout.md) 依赖方向那一条：`core` → `contact` → `accounts` →
> `org` → `events`，「**谁也不许反向 import**」。

而这一页要读 `events`、`notices`、`org` 三个 app 的模型。放进 `core` 就是让
依赖链的**根**去 import 它自己的三个下游 —— core 从此既是根又是顶。

⚠️ `core/context_processors.py` 已经 import 了 `org.permissions`（导航菜单要问
权限）。那是一处**既存的破例**，而且只 import 一个纯函数模块；
不该在它上面再叠三个 app 的模型。

落点因此是一个新 app，排 `INSTALLED_APPS` 最后。三条理由，第三条是白拿的：

1. 仪表盘的本质是**聚合器** —— 它必须能读所有人，所以它必须在依赖链末端。
   `gallery/admin.py` 已经写下了这个形状：「Nothing depends on gallery,
   which is why it is last」；
2. 于是 D17 那条规矩一次都不用破；
3. ⭐ **它没有 `models.py`，而那是承重的**：一个没有模型的 app 长不出表，
   于是「仪表盘不拥有数据、它只是别人数据的一个视图」从一句约定变成了结构事实。

⚠️ 这也是本项目第一个无模型的 app。它合法，而且正好证明了这个 app 只是视图层。

## 二、五张卡，以及每一张为什么在

顺序**固定**，按紧急程度：你必须知道的 → 你承诺了什么 → 别人在等你 →
好消息 → 回顾。

| 卡 | 谁读它 | 数据 |
|---|---|---|
| Notices | 所有人 | `Notice.objects.showing().for_audience(contact)`，最多三条 |
| Coming up | 所有人 | `Participation.objects.mine(contact).upcoming()`，最多四条 |
| Volunteer hours | 所有人 | 见[第四节](#四volunteer-hours-只认一个账本) |
| Needs you | ministry admin | `EventRole.objects.understaffed()`，加「结束了但没 wrap up」 |
| Recent signups | ministry admin | 我管的活动最近四条报名 |

通栏上还有一条**在编的人的职位**。🔴 列出他持有的**每一条**任职，不是
`.first()` —— [D32](D32-worker-axes-schedule-and-assignment.md) 的不变量是一人
可以同时多岗，而 `.first()` 在这张表上是 bug：它在页面上把一个人的第二个身份
悄悄抹掉，什么都不报。
⚠️ 外部志愿者这一整行**不出现**，不画一句「你没有职位」——
D27：没有和没算不能长得一样，而「不是在编」本来就不是一种缺失。

### `Needs you` 一个新口径都不造

两类都借既有的：`understaffed()` 是 `events/models.py` 里已经有的（报名页那个
short 徽章读的是同一个 annotation）；「结束了但跟进没做完」直接借
`Event.Status.COMPLETED` 的既有语义 —— 那个状态的注释写死了它就是
「出勤记了、工时记了」，所以「过了时间、状态还不是 COMPLETED」本身就是这句话的
反面。⚠️ 这是本轮唯一一处**本来很想造一个新口径**的地方
（一开始想自己算 `hours_missing`），而那会是这份报表之外的第三个说法。

### foundation tier 不加专属卡片

说不出他每天要在首页看什么。入口在侧边菜单已经有了。

## 三、排版：卡片网格 + 一条窄侧栏

参考了两张现成产品的截图，而它们各贡献的**恰好是自己做对的那一半**：

| 参考 | 学它什么 |
|---|---|
| 一张 “My dashboard” 的卡片网格 | 卡片本身的语言：彩色小图标 + 名词标题、卡内两到四行、每行主次两级、行尾一个 `›`、卡底固定位置一条出口 |
| Planning Center Services | 一条**窄侧栏**放小月历 + 一个「看完整日历」的框线按钮 —— 时间导航和内容分开，主区不被日历占掉 |

几条落到代码里的：

- 出口链接抽在 `_card.html` 一份，靠 `flex-col` + 内容 `flex-1` 推到底。
  ⚠️ 让每张卡自己去对齐，第二张就会差半行 —— 那是「单独看都没问题、
  放在一起就是业余感」的来源；
- 图标是 emoji 装在一个彩色圆角方块里，**不引图标库**：这一页要五个图标，
  为五个图标引一个字体文件是每一个访客都在付的账。颜色是**认卡用的**，
  所以每张卡的色档全站固定；
- 手机上侧栏排到**最下面**（`order-last`）。月历和订阅按钮不该占掉第一屏。

### 侧栏那个月历是跳转控件，不是第三个日历页面

它画当月格子、在有报名的日子上点一个点、点哪天都跳到 `/events/schedule/`。
**不翻月、不显示活动名、不可点开某一场** —— 那些是 `/events/schedule/` 的活。
⚠️ 多一颗能翻月的按钮，就是在这里重新长出那一页。

> 🔴 月历的点子**不能**从「Coming up」那张卡的列表里取，虽然那样省一次查询。
> 那个列表被截到四条，于是月历最多标得出四天，而少标的那几天**没有任何迹象** ——
> 它看起来就是一个正常的、那天没事的月历。第一版就是这么写的，
> 注释还写着「两块并排的东西画的是同一批报名」：那句话本身是对的，结论是错的。
>
> ⚠️ 而且两块问的根本不是同一个问题：卡片问「接下来最近的四件事」，
> 月历问「我这个月哪几天有事」—— 包括这个月**已经过去**的那几天。

## 四、Volunteer hours 只认一个账本

标题是**账本名**，不是「My hours」。

[D36](D36-two-hour-ledgers.md) 写死 `Participation.hours` 和 `Shift` 会重叠、
永远不许相加，而 `Shift` 那本要等 D2a。叫「My hours」是在暗示这是全部（它不是）；
叫账本名则是一句 **D2a 之后一个字都不用改**的真话 —— 那时 `Work hours` 并排加
进来，天然不相加，正是 D36 要的形状。

口径是 `ParticipationQuerySet.volunteering()` + `hours_given()`，新写的。

> ⚠️ 原计划写的是「走报表已有的那个服务函数」，而**那个函数不存在**。
> `events.services.ministry_report(events)` 收的是一个已筛过的**活动** queryset、
> 答的是「这个 ministry 这段时间的总况」，它的 `hours_total` 聚合的是 helping
> 那一半的全部工时，**不分志愿还是工作**。按人算、且只数志愿那个账本的口径，
> 本仓库一条都没有。
>
> 🔴 而 `volunteering()` 的安全性正在于它**只认一档**：想要两档相加的调用方
> 在这里找不到方法可用，而那正是 D36 禁止的那个和。

### 累计，不是「本年度」

原计划写的是本年度。⚠️ 「年」从来没有人定义过 —— 日历年？基金会的财年？
所以不发明一个边界：显示累计。一月一号清零会让人觉得自己的贡献消失了，
而累计只增不减，作为一个 impact 数字反而更对。
真要年度是一个明确的需求，那时加一个筛选。

## 五、代价（如实记）

1. **多一个 app**，且是第一个没有模型的。换来的是 D17 一次都不用破；
2. **这一页是全站查询最多的一个**（ministry admin 约 17 次）。上限钉在
   `dashboard.tests.TheQueryBudgetTests`，⚠️ 那是一个**回归**测试不是性能测试：
   仪表盘天生是「再加一张卡」的地方，而每张卡都是一次查询。数字爬升的那一次
   该问的是「这张卡值不值这次查询」，不是把上限往上调；
3. **`my_participations` 的判据搬了家**。它现在是 `ParticipationQuerySet.mine()`，
   两个页面共用 —— 而 `AudienceIsAskedGuardTests` 的豁免名也跟着从
   `my_participations` 改成 `mine`。⚠️ 留在旧名上会**豁免一个不再问这个问题的
   函数、同时红掉真正在问的那个**；
4. **装配全在 `services.py`，视图只有两条语句。** 这不是洁癖：
   `ViewsAreThinGuardTests` 拦着 views.py 里的日期运算和聚合，而这一页有五处要
   问「现在」。⚠️ 各问各的话，问候语、月历和 `upcoming()` 有可能落在午夜两侧 ——
   一年发生一次，且没有任何东西会报错。所以 `now` 在服务层取一次，往下传。

## 七、2026-09-11：这一页也出现在 `/` 上，视图搬进了本 app

见 [D44](D44-the-front-page-scrolls-into-the-dashboard.md)。登录的人在 `/` 往下滚
就能看到这一页的内容，`/me/` 保留、URL 不变、登录后仍然落在这里。
三处改口写在这里，不只写在那边：

- **`/me/` 不再自己渲染仪表盘了，它是一条回 `/` 的跳转**，登录之后也落在 `/`。
  本文件标题那句「`/me/` 是登录后的落脚点」因此只剩地址还在：落脚点是 `/`。
  改口的理由是一句话 ——「我现在在 home page 完全不能 scroll up 看到 hero image」：
  仪表盘住在自己的地址上时，它是一张没有上半身的页面。⚠️ 本节其余几条（四条门槛、
  卡片的取舍、侧栏月历的分寸、查询预算）一条都没变，变的只是它画在哪一页上。
- **渲染 `/` 的视图搬进了 `dashboard`。** 本文件第一节写着仪表盘不能放 `core`，
  因为那会让依赖链的根 import 它自己的三个下游 —— 那条理由一个字没变，
  所以搬的是另一头：`/` 的视图搬到末端来，方向从此是「末端 import 根」，顺着 D17 走。
  考虑过让 `dashboard` 提供一个模板标签、把 `/` 留在 `core`，没有采纳：
  `{% load %}` 在渲染时照样 import，依赖没有消失，只是 grep 查不到了，
  而它失败时炸的是全站最公开的那一页，连匿名访客一起炸。
- **第四节那个「显示累计、不发明年度边界」改口了。** 现在两个数都印：
  大字是日历年（1 月 1 日至 12 月 31 日，基金会本地时区），小字是累计。
  原来那条顾虑（一月一号清零会让人觉得自己的贡献消失了）由小字那一行接住。
  🔴 两半必须**各按自己的日期**算：报名那一半按活动的 `start_time`，
  出勤那一半按 `session__start_time`，否则一门跨年的课会被整期算进它开课的那一年。
- **`Needs you` 从一张 admin 专属的卡变成通栏一大块**，并且有了第二种形态：
  ministry admin 读到的还是「还缺人的工种 + 结束了没收尾的活动」；
  其余所有人读到的是「还缺人、他看得见、他还没报名的活动」。
  后者会和 `Happening soon` 说同一件事，所以那张卡要排除掉上面已经列出的那几场 ——
  它本来就在排除「我报过的」，同一个模式。

| foundation tier 的专属卡片 | 说得出他每天要在这一页看什么的那天 |
