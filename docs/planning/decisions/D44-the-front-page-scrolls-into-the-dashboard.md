# D44 · 首页往下滚就是仪表盘，视图搬进 `dashboard`（2026-09-11）

结论：`/` 对**登录的人**向下延伸出仪表盘，成为一页；**未登录的人看到的 `/`
一个像素都没变**。渲染 `/` 的那个视图从 `core.views.home` 搬到 `dashboard.views`，
URL 名 `home` 不变；`/me/` 保留成一条回 `/` 的跳转，登录之后也落在 `/`。

从 hero 滚进仪表盘的那一下**什么都不发生**：两半各自是原来那一页，一个像素不动。
入场动画做过五版，2026-09-12 整套撤销 —— 经过在[第四节](#四入场做过五版2026-09-12-整套撤销)。

## 二、为什么视图搬进 `dashboard`，而不是另外三条路

[D17](D17-app-layout.md) 写死依赖方向 `core → contact → accounts → org → events`，
**谁也不许反向 import**；`dashboard` 排在末端，因为它要读 `events` / `notices` / `org`
三家的模型。而 `/` 原来是 `core.views.home` —— 要在服务端把仪表盘渲染进这一页，
就得让依赖链的**根**去 import 它自己的下游，那正是 [D42 第一节](D42-signed-in-landing-page.md)
花一整节避开的那一句。四条路都摆出来过：

| | A · HTMX 懒加载 | B · 视图搬进 `dashboard` ✅ | C · 新开一个组装 app | D · `dashboard` 出一个模板标签 |
|---|---|---|---|---|
| 访客看到的 | 相同 | 相同 | 相同 | 相同 |
| 依赖方向 | 没有这份依赖 | 末端 import 根，**顺向** | 顺向 | 逆向，只是不写成 import 语句 |
| grep 查得到吗 | 不适用 | 查得到 | 查得到 | 查不到，**下一个人问「谁在依赖 dashboard」时会漏掉首页** |
| 坏掉的时候 | 片段拿不到，hero 照常 | **启动时** import 失败，测试第一条就红 | 同 B | `{% load %}` 渲染时才炸，炸的是最公开的那一页，**匿名访客一起炸** |
| 代价 | 没有 JS 时 `/` 下面是空的 | D25 / D42 各补一节 | 多一个无模型 app | 文件不用挪窝，仅此而已 |

选 B 的那一句话：**在启动时吵闹地失败，好过在最公开的那一页安静地 500。**
D 的诱惑在于「`core/views.py` 里一行 import 都没有」，而 `{% load dashboard_tags %}`
在渲染时照样 `import dashboard.templatetags.dashboard_tags` —— 依赖没有消失，
只是从静态可查变成了运行时才发生。把一份依赖藏起来，不是把它去掉。

A 是唯一真的没有这份依赖的做法，代价是那一块要靠第二个请求；
2026-09-11 权衡后选了 B：不依赖脚本就能看见，比省下这一次 import 值钱。

## 三、版面：一页三段

    ① hero 满屏     照片/视频 + 经文 + 顶栏 + 侧边菜单   —— 未登录的人只有这一段
    ② 问候那一段     日期 · Good evening, Grace · 工时 · Needs you 通栏
                    ⚠️ 通栏**只有一行**：三格内容加一格出口。见第七节
    ③ 卡片区         左侧月历 + 右侧卡片网格

⚠️ ① 和 ② 之间曾经还有一段「接缝」，2026-09-12 整套撤掉了 —— 现在那里是一条硬边，
   知情的中间状态。撤的经过和还没解决的那件事在下一节，代码里写着同一句话。

🔴 **通栏和下面的卡片左右对齐，靠的是一层公共版心。** 原先问候区、通栏、卡片网格
   各写一份同样的 `max-width + padding-inline`，看起来「三处一致」，实际上对不齐：
   通栏的**边框**画在它自己的外沿，而卡片在网格那一层的内边距**里面** ——
   通栏因此比卡片左右各宽出 16px。走查时一眼看得出来，而三处各自看都没问题。

🔴 **接缝在问候语之前，不是之后**（2026-09-11 当天改口）。第一版把问候语和
   Needs you 压在照片上、照片在它们**下面**才化掉，而要的顺序正好相反：
   照片先化掉，这一页才开始说话。用户的原话是「这个渐变不应该在 Good evening 和
   needs you 下面，应该在上面」。
   于是那一段从「白字加投影压在照片上」换回了正常的正文配色 ——
   浅色下就是页面底色上的深字，深色下是同一张压暗照片上的浅字（和每个内页一样）。

照片从 `absolute` 改成 `fixed`：内容从它上面滚过去，而它不动。这既是「高级感」的
来源，也是接缝将来唯一可能糊得住的前提 —— 照片跟着滚的话，糊的位置每一帧都在变。

### 🔴 一页只能有一个地址（2026-09-11 当天改口）

`/me/` 原本保留成第二张自己渲染的仪表盘，同一份 partial 两个壳。**那是错的**，
而错在一句话上：

> 我现在在 home page 完全不能 scroll up 看到 hero image。

「连在一起」的意思是**同一页的内容**，不是两页之间有个动画。登录之后落在 `/me/`
的人看到的是一张没有上半身的页面 —— 而那张照片明明就在同一个站里，只是在另一个
地址上。所以：`/me/` 改成一条回 `/` 的跳转，登录后的落点、菜单里的 Home、
以及 `accounts/views.py` 里那六处跳转全部改指 `/`。

⚠️ 这条路**留着**而不是删掉：它进过菜单、进过六处落点，也可能在谁的书签里。
删掉是 404，跳转是「你要的东西在那边」。`@login_required` 也留着 ——
没登录的人点旧链接要的是自己那一屏，不是那张照片。

⚠️ 于是「一份 partial 两个壳」那个顾虑消失了，连同它的守卫思路：现在只有一个壳。

🔴 **`on_photo` 那个参数和 `me.html` 一起删了（2026-09-12）。** 它留过一天，理由是
   「partial 本身没有理由假设背后一定是照片」—— 而这一天里它只有一种取值，
   第二条路一次都没有人走过。一个永远为真的开关不是灵活性，是读的人必须在脑子里
   跑两遍的分支：模板里一个 `{% if %}`、CSS 里八条 `.deck--on-photo`、JS 里一个
   选择器，外加 `me.html` 那个从此没有任何视图渲染的壳。真要回到两种形态时，
   那时的第二种长什么样，比今天预留的这一个准。

### 🔴 照片自己的底色向外渗出去，而不是淡出到一块纸

四版接缝都在同一个坑里：结构是「固定铺满的照片 + 一条盖在它上面的东西」，
而那条东西不透明度涨到 1 的那一行**就是一条边**。第四版改成「照片淡出、露出纸」，
边没了，但用户的判定是：

> 照片底的颜色直接没了？应该是照片自己的底的颜色向外渲染变浅。

对的 —— alpha 归零意味着**颜色也归零**。要的是那些颜色**继续存在**，只是越来越淡。

### 第五版（渗色条）做出来了，然后被整个撤掉

做法是取照片底部那一条**逐列**的颜色，向下延伸并化进纸色：左边是深树就渗深色，
中间是白雾就渗灰白。CSS 渐变做不到逐列（同一个 y 上的颜色横跨整幅必然相同），
所以它只能是一张后端出的图 —— `core/tail.py`、`HomePage.hero_tail`（约 40KB）、
`hero_ratio`，外加「两张图必须落在同一个横向缩放上」而手写的那套 `cover`。

实现完、跑绿、上浏览器看，判定是一句话：

> 这个渗色条真的很丑，整个删掉。

于是 `core/tail.py`、两个模型字段、两条迁移（未 apply 就撤）、两个 context 值、
那套手写 `cover` 的 CSS 全部回退，`colours_from()` 回到只返回 `(dominant, edge)`。

🔴 **剩下那一半 2026-09-12 也删干净了。** 撤渗色条时留下了底部取色那一条链：
   `hero_wash_colour` 字段、迁移 `0009`、`palette.wash_from()` / `edge_colour_of()` /
   `colours_from()`、context 里的 `site_hero_wash`、`_appearance.html` 那行
   `--hero-wash`、CSS 里的 `--deck-top`，还有四条测试。它们都还跑得通、也都还绿着，
   而**没有任何一个使用者**：`--deck-top` 的 `var()` 引用数是 0 —— 接缝是它唯一的
   去处。`refresh_palette()` 因此回到 `dominant_colour()` 一次解码，
   `HomePage.MEDIA_FIELDS` 仍然是两项。
   ⚠️ 判据一个字没变：颜色要继续存在、只是变淡。真做第六版时要的是纸色那一层的
      边被噪声推碎，照片原样露出来 —— 那条路一个后端字段都不需要，所以这些东西
      即使留着也不会被它用上。

🔴 **没有被推翻的是那条判据**：颜色要继续存在、只是变淡。推翻的是「让后端算出
那些颜色」这条路 —— 它的代价（一张派生图、一个宽高比字段、竖直取景从此锁死在底部、
`MEDIA_FIELDS` 多一项要登记的公开文件）全都押在一个只能靠眼睛判定的效果上。

### 现在在试的：把纸色那一层的边用噪声推碎

正在模拟器里调的是第六版：不再算照片的颜色，而是让**纸色那一层自己的边**
不成其为一条边 —— 一个 `feTurbulence` + `feDisplacementMap`，把那一层的上沿
按噪声横向和纵向推开，推出毛边和飞白。照片在它底下原样铺着，露出来的那一截
就是照片自己的颜色，深浅随列而变 —— 这是渗色条想要的结果，但不需要任何后端。

⚠️ 那一层要**往下多垫一截**（模拟器里是 140px）再用遮罩把可见高度切回来：
位移最多能把纸色往上拽 `scale / 2`，垫不够就在最下面漏出一条照片。

⚠️ 在定下来之前，首页的 hero 和仪表盘之间**是一条硬边**，没有任何过渡。
这是明知的中间状态，CSS 里写着同样的话。

🔴 **深色模式下这一整套不存在**：那时照片是整页的背景（同内页），上下是一整片，
没有「结束」这回事，也就没有什么需要渗。

## 四、入场：做过五版，2026-09-12 整套撤销

结论：**这一段没有任何动画。** 仪表盘的每一块在它自己的版面位置上渲染出来，
读者滚到哪里就看到哪里。

### 撤的是这件事本身，不是第五版没做好

第五版做完、跑绿、上浏览器看过之后，判定是一句话：

> 要一模一样，而且不要任何动画。

「一模一样」指的是随这句话一起给的两张截图：hero 就是原来那一屏（照片、经文、
顶栏），仪表盘就是原来 `/me/` 那一页（问候、工时、Needs you、三张卡加月历）。
**连在一起之后两半都一个像素不动** —— 这正是入场动画做不到的事：它的全部内容
就是让下半页在读者滚到之前处在别的位置上。所以这一格空着是结论，不是等下一版。

⚠️ 撤掉的只有「hero 和仪表盘之间那一下」。页面上其余的动效**一个都没动**：
经文淡入、飘着的羽毛、顶栏淡入淡出、侧边菜单逐条入场都还在 ——
那几样是那两张截图里那两页本来就有的，撤了才会不一样。

### 被推翻的五版，按顺序记下来

| 版本 | 形制 | 判定 |
|---|---|---|
| 一 | 逐帧刚体：重力 + 回弹 + 一维堆叠 | 「像很重的东西砸在地上，类似于皮球」 |
| 二 | 一次性缓动，1 秒，行程 56–80px | 「效果不对」 |
| 三 | 一次性缓动，5 秒，三维翻转 | 「向上抛的动画压根没看到」 |
| 四 | 滚动驱动，起点 74–96vh | 「为什么还遵循实际页面的上下结构」 |
| 五 | 滚动驱动 + 在空中不排页面结构，参数全部来自一台模拟器 | 「不要任何动画」 |

前四版的代价不在实现上，在反复推翻上：每一轮都要动一遍真代码、跑一遍测试、
再推翻一遍。第五轮改了做法 —— 先把动画从代码里删掉，做一个模拟器，在里面把参数
调到位，再一次性实现。**那个做法是对的，它省下的正是第六轮**：这一次要改的不是
参数，是有没有这件事，而回答这个问题一行代码都不用写。

🔴 真要再来一次的话，先读这张表：**五次里有四次是效果本身被否掉，不是数值不对。**
   这是一个「靠眼睛判定、而且判定过五次都是否」的效果。

### 代码里现在是什么样

| 曾经在哪 | 现在 |
|---|---|
| `app.css`：`@keyframes drop-in` + `.deck .drop` + `view-timeline` + `@supports` | 一段注释，记着上面这五版 |
| `app.js`：量每块在空中起点的那个 IIFE（`--sky-*` 六个自定义属性） | 一段注释 |
| 模板：`_deck.html` / `_card.html` / `_needs_you_band.html` 上的 `.drop` | 删了，四处 |
| 守卫 `TheEntranceStaysOutOfJavaScriptGuardTests`（JS 不许逐帧跑） | `TheEntranceStaysGoneGuardTests`（入场不许回来） |

🔴 **`.drop` 这一次跟着一起删。** 撤第四版时它留过一次，理由是「哪几块参与入场
   这件事没有变」—— 留下的是一个没有任何样式挂着的 class，读的人得翻遍 app.css
   才敢确认它真的什么都不做。一个永远不生效的标记不是预留，是一道题。

⚠️ 新守卫盯着 `--sky-*`、`drop-in`、那根时间线和 `.drop` 四样，CSS / JS / 模板
   三处任何一处再出现都会红。**它先剥注释再扫** —— 上面那些名字写在注释里是合法的，
   否则这几段解释会把自己钉红，而一条连墓志铭都不许写的守卫会被下一个人删掉。

## 五、首页开始跟随深色模式，而那句担心是查过的

D25 和 [`_head.html`](../../../core/templates/core/components/_head.html) 都写着
「首页不跟随深色模式，因为 `<html>` 一旦有了 `.dark`，顶栏那套『白字 / 深蓝字』的
规则会全部翻转」。这句话**对顶栏不成立**，查过 `app.css` 里每一条命中 `.home-*` 的
`.dark` 规则：

    .dark .home-bar.is-solid              内页那条实心 bar
    .dark .home-bar.is-solid .home-bar-item
    .dark.has-hero .home-bar.is-solid
    .dark .home-menu / .dark.has-hero .home-menu / .dark .home-menu-heading

前三条都带 `.is-solid`，而首页那条 bar **不传 `solid`**，一条都命中不了；
首页的白字规则写在无条件的 `.home-bar-item` 上。真正会变的只有侧边菜单面板，
它会变成深色玻璃 —— 而对一个开着深色模式的人，那正是它该有的样子。

改口的真正理由是首页不再「只是一张照片加白字」：它下面现在有一整屏卡片。
不跟随主题的话，深色模式的人会从一张暗照片一头撞进一片纯白。

⚠️ 跟随之后，**开关也得给**（2026-09-11）：登录的人右上角多一个主题切换按钮和
自己的名字（顶栏那个 `themed` 开关同时带出这两样，不为拆开它们再加第三个参数）。
跟随而不给开关，等于把选择权收走了。匿名访客那一页仍然只有 Log in，
也仍然不跟随深色模式。

顺带白拿的一件事：`<html>` 上跟着有了 `has-hero`（`site_root_class` 本来就算好了，
首页原来硬写 `h-full` 没用它），于是深色下卡片是压在同一张照片上的玻璃——
和每一个内页一模一样，因为[内页的深色背景](../../../core/templates/core/components/_hero_backdrop.html)
本来就是这张照片。

## 六、工时印两个数，「年」定义成日历年

[D42 第四节](D42-signed-in-landing-page.md)否掉过「本年度」，理由是「『年』从来没有人
定义过 —— 日历年？基金会的财年？所以不发明一个边界」。2026-09-11 定：**大字印日历年
（1 月 1 日至 12 月 31 日，基金会本地时区），小字印累计**。两个数并排，那句顾虑
（一月一号清零会让人觉得自己的贡献消失了）由小字那一行接住。

🔴 **两半必须各按自己的日期算。** `hours_given()` 加的是两张表：报名那一行的
`Participation.hours`，和课程每一次出勤的 `SessionAttendance.hours`。按活动的
`start_time` 一刀切下去，会把一门**跨年的课**整期算进它开课的那一年 ——
而这类课正是 `SessionAttendance` 存在的理由。所以年度口径是
`event_role__event__start_time` 管报名那一半、`session__start_time` 管出勤那一半，
配一条跨年的测试。

口径仍然只认志愿那一个账本（`volunteering()`），[D36](D36-two-hour-ledgers.md)
那个禁止的和在这里依旧不可能写出来。

## 七、`Needs you` 有了第二种形态

截图里它是通栏一大块，而 D42 那张卡**只有 ministry admin 有内容**。定：同一块地方，
两种人读到两句话。

### 🔴 它只有一行，而那是不变量不是样式

最多三条（`dashboard.services.BAND_ITEMS`），因为末尾还要放一格出口，三加一正好排满

⚠️ 「一行」承重的理由不在长相上：这一块横过整幅、又是整屏唯一要人动手的地方，
一旦长到两行，它就开始和下面的卡片网格抢「这一屏在说什么」。
⚠️ 同一个理由决定了它**上下各留 2rem**，而不是网格自己的 `gap-6`（2026-09-12 分两次
   修到位：先补下面那个 0px，再把上面那个 48px 收成一样宽）：通栏不是网格里的又一行，
   它和上下两边都是一道分段。
   🔴 两道缝夹着同一块东西、方向也相同，**不一样宽就读成它偏向下面那一组** ——
      所以它们归通栏自己声明（`margin-block`），问候那一段的下边距是 0。
⚠️ 窄屏当然换行 —— 那时它从一条横幅变成一列卡片，整块的意思没变。

## 八、落点只有一个：`/` 永远从 hero 开始（2026-09-12 推翻本节原文）

结论：**不管从哪里来、第几次来，打开 `/` 都落在 hero 的顶部。**

原文写的是：第一次落在顶部，**同一台设备第二次起直接落在仪表盘那一屏**，
用 `localStorage` 记「这台机器上的人见过那一下没有」。那段脚本连同它的键
（`home-intro-seen`）2026-09-12 整段删了。

### 推翻它的是顶栏正中那个字样

> 点吸顶的 "river of life foundation" 竟然跳到 home page 了，应该像之前一样去
> hero 首页的。

那个字样指向 `/`，而它在任何网站上的意思都是**「回到首页」**。点下去落在仪表盘上，
是这段脚本改写了落点 —— 链接本身一个字没错。

🔴 **教训不在那一个控件上，在[第三节](#三版面一页三段)那条「一页只有一个地址」的
后果上**：`/` 从此同时是首页和仪表盘，于是「打开 `/`」这件事有了好几种来意 ——
刚登录完、从菜单里的 Home 回来、点字样回首页、自己敲地址。那段脚本对它们**一视同仁**
地改写落点，所以它必然会在其中某一种上读成 bug。出路只有两条：每一种来意各自决定
落在哪（那是一张没人要的表，而且每加一个入口就要再判一次），或者一种都不改写。

⚠️ 选后者的代价如实记：**天天用的人现在每次打开 `/` 都要往下滑一次**才看见仪表盘。
   换来的是「打开首页看见首页」没有例外 —— 而那正是这一页的名字所承诺的。

⚠️ 已经存进浏览器的那个 `home-intro-seen` 键留在原地，没有人再读它。不专门写一段
   清理脚本：为一个没有副作用的遗留键跑一遍全体访客的 `localStorage`，比留着它贵。

登录后跳 `/`（原文写的 `/me/` 已在[第三节](#三版面一页三段)改掉），
`TheLandingPageAfterLoginTests` 原样绿。
