# D46 · `Position.code` 是一个可选的锚点，不是从名字派生的标签（2026-09-15）

结论：`Position.code` 改成**可空，而且默认就是空的**。绝大多数岗位没有 `code`；
只有当另一个系统或一段脚本真的要指向某一个岗位时，才由人**特意**设一个 ——
设过之后照旧不可改。**网页表单上永远没有这一格。**

> 本条**修改了 [D5 的「一张不落」](D05-lookup-tables-not-enums.md#通则每张字典表都带一个唯一且不可改的-code)
> 被读成的范围**，并**推翻了 [D11](D11-position-and-assignment.md) 设计块里那行
> 「`code` 唯一·不可改（D5 通则）」** 以及 [`../phase-b.md`](../phase-b.md) 里
> 两处相应的表述。三处都已就地写了修订说明
> （[README 加新决策的第 3 步](README.md#加一条新决策时)）。

## ⭐ 唯一的不变量：一个格子做不了两件事 —— 标识符不许变，描述不许过期

这是本条的全部内容，其余都是它的推论。

- **标识符**（身份证号、`pos_1Abc`、`pantry_lead`）之所以可以永远不变，
  是因为它**不描述任何东西**。没有人期待从号码里读出你是谁，所以你改名、
  搬家，它照旧有效。
- **标签**（名字、职务名）之所以必须能改，是因为它**描述**一个会变的事实。

一个从名字自动生成、然后冻住的 `code` 同时想当这两样，于是**两头都坏**：
它看起来在描述（所以人会当描述读），却因为不可改而必然在某一次改名之后
变成一句假话。

> 说清楚这件事的那个例子：发一种身份证号，长成「北京-张三」。
> 张三改名叫张四之后，这个号码**改不得**（一改，所有引用它的地方全断），
> 又**是错的**（它描述了一个不存在的人）。

⚠️ 这和 [D32](D32-worker-axes-schedule-and-assignment.md) 是同一种病的第二次发作：
那里是**一个字段扛了三个轴**（`kind` 同时说「有没有固定岗位」和「给不给钱」），
结论是拆开。这里是一个字段扛了两种身份，拆法就是**可空**：

| 状态 | 含义 | 谁写它 |
|---|---|---|
| 空（默认） | 还没有任何系统需要指向这个岗位 | 没有人 —— 它本来就是空的 |
| 有值 | 有人**特意**给它设了一个锚点 | 设那个集成的人，在 Django admin 里 |

一个状态一个含义，而不是靠「这个值看起来像不像自动生成的」去猜。

## 一、行业里是两种模式，而判据只有一句话

| | 谁这么做 | 长什么样 | 可不可改 |
|---|---|---|---|
| ① 内容平台 | WordPress · Wagtail · Ghost · Shopify 商品页 | slug 从标题生成，**活在公开网址里** | **可以改**（错了要能修），一般配重定向 |
| ② 企业系统 / API | Workday · SAP SuccessFactors · Stripe | 不透明 id（Workday 的 Position ID）**外加**一个可选人工键（Stripe 的 `lookup_key`、SuccessFactors 的 `externalCode`、Workday 的 Job Code） | 人工键**默认为空**，设了就不动 |

> 判据：**这个东西有没有一个人会分享出去的公开网址？**
> 有 → ①。没有 → ②。

岗位页是 `/staff/positions/<int:pk>/`，只有管理员进得去，**没有任何人会分享
一个岗位的网址**。所以它属于 ②，而本条就是 ② 的形状。

⚠️ 「一个通常是空的列」读起来别扭，是因为 ① 太常见了 —— 我们天天见到 slug。
但 Stripe 的 `lookup_key` 正是一个通常为空的列，绝大多数 Price 根本没有。
空不是「没填完」，空是**一个真实且常态的答案**。

## 二、当初为什么给 `Position` 一个 `code`，以及那个理由后来怎么了

原话在 [`../phase-b.md`](../phase-b.md)：

> `Position` 不是字典表，但 `code` 的作用一样：代码只认 `code`，不认 `name`
>
> `Position` 的代码锚点是 `code` 不是 `name`，所以 `name` **不加**唯一约束

理由是成立的：`Position.name` **故意不唯一**（两个 ministry 各有一个"协调员"），
所以需要一个东西让代码能稳定地指向某一个岗位。

⚠️ **但那是一个关于将来怎么写代码的预期，不是当时就在用的事实。**
到 2026-09-15 为止，全仓库按 `Position.code` 匹配的只有
`events/management/commands/seed_demo.py` 那五句 `get_or_create(code=…)`，
而那个命令 `DEBUG` 关掉就拒绝运行。

而这五句**恰恰是本条要保护的那种用法**：`pantry_lead` / `pantry_staff` /
`pantry_driver` / `pantry_helper` / `pantry_intern` —— 手挑的、有含义的，
而且**一个都不是 `slugify(名字)` 会产生的东西**。

## 三、被否掉的三条，各自死在哪

| 方案 | 死因 |
|---|---|
| 自动生成 `coordinator` / `coordinator-2` | 唯一，但既没有含义也**不可复现** —— 那个 `-2` 编码的是建立顺序。换一个库重跑 seed，编号可能落到另一个岗位身上，**脚本照常跑完，数据静静地接错人** |
| 自动生成带 ministry 前缀 `food-pantry-coordinator` | 有含义、也可复现（从 ministry + 名字算），**两个毛病都治好了** —— 但它正是上面那个「北京-张三」：一旦冻住，改名之后就是一句过期的描述，而且因为它看起来很像描述，比不透明的编号**更**误导 |
| 删掉这一列 | 那就再也没有锚点了，代码只能写 `get(ministry=…, name="Coordinator")` —— 按显示名匹配，正是 D5 整条决策要防的事。而且删列的改动最大（删列迁移带影子表 + 约束 + `CONSTRAINT_FIELD` + admin 搜索 + `seed_demo` 五处 + 测试十几处） |

## 四、落地

- `Position.code`：`null=True, blank=True`，`help_text` 改成「留空。只有当别的
  系统或脚本要指向这个岗位时才需要，而设那件事的人知道该填什么」；
- `org.forms.PositionForm` 上**没有这一格，两档权限都没有**。
  「什么时候该填」是一个技术判断（有没有别的系统要指向它），而 foundation admin
  答不出它 —— 给他看这一格等于请他猜；
- `PositionAdmin.get_readonly_fields` 从 `if obj` 改成 **`if obj and obj.code`**：
  空着的时候填得了（那是设锚点唯一的路），填了就冻住；
- `core.models.ImmutableCodeMixin.save()` 把空值归一成 `None` —— **当且仅当这一列
  可空**，判据取自字段本身。⚠️ 不这么做的话 `""` 和 `None` 两种空法并存，而
  `UniqueConstraint(Lower("code"))` 只放行**一行** `""`（Postgres 认多个 NULL
  互不相等，但认两个 `""` 是重复）；
- `code_change_error()` 一个字没改，而它的 `stored is None` 那一支**有了第二个
  含义**：本来只是「这一行不在库里」，现在同时是「这个岗位还没有锚点」——
  两者都该放行，理由是同一条：不可改保护的是**已经有人在引用的那个值**。

**迁移无回填**，既有的值一个都不动（`seed_demo` 那五个正是现在想要的那种值）。
`position_code_ci_unique` 一个字不用改。

## 五、代价（如实记）

1. **绝大多数岗位没有一个可读的句柄。** admin 列表上那一列大面积是空的，
   而按名字搜索仍然可用（`search_fields` 本来就含 `name`）；
2. ⚠️ **「什么时候该设一个锚点」没有写在界面上，因为它写不出来。**
   本条的处置是把这一格从所有非技术的界面上拿掉，而不是给它配一句谁也看不懂的
   提示 —— 但这意味着**新来的工程师要读到这一条**才知道那个口子在 admin 里；
3. **两个岗位同名时，代码没有现成的办法指向其中一个** —— 要么给它设一个锚点，
   要么用 `pk`。这是主动接受的：没有锚点的岗位本来就没有任何代码在指向它。

## 六、推迟的，以及重启条件

| 事情 | 何时重新考虑 |
|---|---|
| 给岗位一个公开网址（于是真的需要 slug） | 真的出现「把某个岗位的招聘页发给外面的人」时。**那时走 ① 那一套**，而且 slug 和本条的 `code` 是**两列**，不是一列 —— 本条唯一的不变量就是这么说的 |
| 界面上给 foundation tier 一个设锚点的入口 | 真的出现一次「工程师不在、而基金会自己要接一个系统」时。⚠️ 那时要一并想清楚**怎么告诉他该填什么**，否则就是把本条第五节第 2 条的代价换个地方付 |
| `Ministry.code` / `EmploymentType.code` 跟着改 | ⚠️ **大概率永不** —— 那两张是真的字典表，`filter(code="food_pantry")` 那种写法就是冲着它们去的，D5 的三条要求对它们全部成立 |
