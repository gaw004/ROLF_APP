# D47 · 单场活动的管理授权：第三张表，不是 `MinistryRole` 上的一档（2026-09-15）

结论：ministry admin 可以把**某一场**活动（或某一门课）的完全管理权交给指定的人。
落在新表 `events.EventGrant` 上，判断照旧只写在
[`org/permissions.py`](../../../org/permissions.py)。

> 本条**给 [D20](D20-ministry-role.md) 的判据补了第三档**，
> 并**改写了 [`../phase-c.md`](../phase-c.md) 那张「谁能看未成年人数据」的表**。
> 两处都已就地写了修订说明（[README 加新决策的第 3 步](README.md#加一条新决策时)）。

## ⭐ 唯一的不变量：范围是**一场活动**，而它会自己到期

一条授权给的是「这一场」——同一个 ministry 的**别的**活动对被授权人是 403。
而它管到这场活动标成 **Wrapped up** 为止，或者被撤销为止，以先到的为准。

⚠️ 「会自己到期」不是一个附带的便利，它是这条决策**敢把范围定得这么宽**的理由：
被授权人在那一场活动上看得到未成年人的标记、紧急联系人电话、以及通知预览里
家长的邮箱和电话（[`../phase-c.md`](../phase-c.md) 那张表）。
如果授权是永久的，这个基金会会慢慢攒下一批永远看得见这些东西的人。

## 一、为什么是第三张表，而不是 `MinistryRole` 上的一档

[D20](D20-ministry-role.md) 自己写下了判据：

> 测试：这个句子里含不含「of some ministry」？含就属于这里。

而「某**一场活动**的完全管理权」过不了那个判据——它比一个 ministry 窄。
D20 的两条边界因此要补成三条：

| 句子的形状 | 落在哪 |
|---|---|
| 没有范围（「谁可以任命 ministry admin」） | Django `Group`（全局那一档） |
| 「某个 ministry 的……」 | `org.MinistryRole` |
| 「某**一场活动**的……」 | `events.EventGrant`（本条） |

⚠️ 表放 `events` 而不是 `org`，因为**它的主语是一场活动**（[D17](D17-app-layout.md)：
一个 app 一个业务域）。对照：`MinistryRole` 在 org，因为它的主语是 ministry。
判断仍然只在 `org/permissions.py`——那条 grep 守卫现在盯着两张表。

## 二、「完全一致」几乎是免费的，而那是 D20 买来的

用户定的范围是「和 ministry admin 对这一场完全一致」。落地时改的是**一个函数**：

```python
def can_manage_event(user, event):
    return (administers(user, event.ministry_id)
            or event.pk in event_ids_granted_to(user))
```

编辑、开工种、签到、出勤、记工时、群发通知——**那些页面一个字都不用动**，
因为它们全部走这一个判断。

⚠️ **如果当初那些检查散在各个 view 里，这个功能就是二十处修改** ——
而漏掉的那一处是静默的：没有人报错，只是某个人打开了一页他不该打开的。
这正是 [D20](D20-ministry-role.md) 坚持「判断只有一处」买到的东西，
而本条是它第一次真的被兑现。

### ⚠️ 但有一处配对，而它差点被漏掉

`events/views.py` 的管理列表上有 `can_manage_event()` 的**列表版**
（一次集合判断代替每行一次查询），而 `administers_one_of()` 自己的注释就写着
「Change one, change the other」。两个都改了：`holds_grant_on()` 和它并排放着。

## 三、被授权人拿不到的三样，各有各的判断

| 拿不到 | 判断 | 为什么 |
|---|---|---|
| 发布新活动 | `can_publish_event()` | 授的是一场活动，不是这个 ministry 的通行证 |
| 管理系列 / 重复规则 | `can_manage_series()` | 系列是这个 ministry 的排期，比一场活动大 |
| 再**转授**给第三个人 | `can_grant_event_admin()` | 🔴 同 ministry admin 不能任命 ministry admin：一个能自我繁殖的权限，**没有人数得清最后有多少人能看未成年人的紧急联系人** |

## 四、发布窄、收回宽

| | 谁做得了 |
|---|---|
| 授权 | 只有这个 ministry 的 admin。⚠️ **foundation tier 也不行** —— 一场活动交给谁办是这个 ministry 的事，而他本来就读得到这场活动的一切，他缺的不是知情权 |
| 收回 | 这个 ministry 的 admin **外加 foundation tier** |

⭐ 形状和理由照 `can_publish_notice()` / `can_manage_notice()` 那一对
（[D41](D41-notices-are-not-events.md) 落地时立的），那一对的原话是
「taking down a wrong or harmful notice cannot wait for the admin who wrote it
to answer the phone」——**一条不该再有的权限同样等不了**。

⚠️ 两个函数，即使今天只差一个 `or`：将来授权哪天放宽给 foundation tier 的话，
收回必须仍然更宽。合并会把这两件事焊在一起。

## 五、🔴 撤销当场生效，而这是落地时撞上的一个既有问题

`in_effect_on()` 的 `end_date` 是**右闭**的——「有效期到 3 月 15 日」的日常含义是
15 号那天还算数。对**事实记录**这是对的：一段任职「做到 15 号」，15 号当天不算
在职的话工时会少算一天（`core/tests.py` 的
`test_active_includes_a_row_ending_today` 钉着它 —— ⚠️ 那条测试2026-09-17 随 [D51](D51-date-ranges-are-half-open.md) 翻了面，现在叫 `test_active_excludes_a_row_ending_today`）。

⚠️ **而撤销把 `end_date` 填成今天。** 按右闭读，那等于
「今天剩下的时间里他照旧有权限，明天起失效」。按钮说「撤销」，发生的是
「明天起撤销」，**而页面上没有任何地方说这件事**。安全上这叫 revocation lag，
而真实系统（Okta / AWS IAM / 门禁）一律是即时的。

🔴 **`MinistryRole` 一直是这个行为，而没有任何测试钉着它** ——
它不是本条引入的，是本条落地时撞上的。两张授权表现在一起改，
补的测试是 `PermissionTests.test_revoking_takes_effect_at_once_not_tomorrow`。

### ⭐ 而它能这么改，是因为授权表单上**没有截止日期那一格**

> 🔴 **本小节的论证被 [D51](D51-date-ranges-are-half-open.md) 改写了（2026-09-17）。**
> 下面这两个谓词只存在了两天：D51 把语义轴整个消掉，`active()` 自己就是右开的，
> **没有第二个谓词可选**。「撤销当场生效」这个结论一个字没变，变的是它的依据 ——
> 右开是全项目的读法，不是这张表靠「`end_date` 只有一个来源」挣来的特例。
> 原文留在下面，因为本文件的价值正在于「为什么改口」。

```python
core/querysets.py::DateRangeQuerySet.in_force()   # 授权走这个：end_date 右开
core/querysets.py::DateRangeQuerySet.active()     # 记录走这个：end_date 右闭
```

两个谓词只在「`end_date` 正好是今天」的那一行上不同。而在授权表上，那一行**只有
一种含义**：今天被撤销了——因为那一列在这两张表上只有一个来源，就是撤销。

> ⚠️ 而「加一个查询集谓词却不加它的行级双胞胎」在第二天（09-16）就咬了一次：
> 撤销当天那一行写着「In effect: Yes」，正下方横幅写着「即刻生效」。
> 经过和守卫见 [D51 第一节](D51-date-ranges-are-half-open.md#一为什么不是把语义轴参数化)。

⚠️ **第一版试过用 `updated_at` 的那一天当判据，不成立**：
`TimeStampedModel.updated_at` 是 `auto_now`，任何一次保存都会写它，
`update_fields` 也拦不住。被一条测试当场抓到。

⚠️ 另一条路是加一列 `revoked_at`。不加，是因为那一列的存在**只是为了补救
表单上那一格**——去掉那一格，整个问题不存在（用户当天拍的板）。

⚠️ 记录本身一个字不改：那一行仍然写着 `end_date = 今天`，因为那是事实。
到期的是权限，不是记录。

## 六、入口，以及「没有入口的权限等于没有」

| 入口 | 谁看得到 |
|---|---|
| 一场活动那一排导航上的 **Admins** 一格 | 只有能**授权**的人（`can_grant`），**不是** `can_manage` —— 给被授权人画一个必定 403 的链接，读起来是「站坏了」而不是「这一页不归你」 |
| 管理列表 `/events/manage/` | 被授权人在这里**只看得到他那几场** |
| 仪表盘通栏「Needs you」 | 「Handed to you to run」一条 |
| 授权当时的一封信 | 发给被授权人本人 |

🔴 **`_scoped_events()` 的第三支是这个功能真正的一半。**
在此之前它对「没有 `MinistryRole` 又不在 foundation tier」的人直接拒绝——于是一个
被指名管理某场活动的人**走不到任何页面**：权限对、页面在、没有任何东西指向它。
而那正是 [`../phase-d.md`](../phase-d.md) 第四节点名三次、
`core/context_processors.py` 开头列了五个的同一种缺口。

⚠️ **两个通知落点都要，理由是它们错过的方式不一样**（用户拍的板）：
一封信会被归档、被漏看；而只有仪表盘的话，一个不常登录的人会在活动前一天才
发现自己该办它。

## 七、代价（如实记）

1. ⚠️ **未成年人数据的可见范围变宽了** —— 见[第一节](#-唯一的不变量范围是一场活动而它会自己到期)
   和 [`../phase-c.md`](../phase-c.md) 那张表。缓解是范围只有一场、而且会自己到期；
2. **每一个管理页多一次查询**（「他被授了哪几场」）。和权限判断本来那一次同量级；
3. **只能授给有登录账号的人**。授一个登不进来的人，那一行是死的，而页面上不会说
   它是死的——所以名单直接收窄（用户拍的板）。⚠️ 代价：想「先把权限安排好、等人
   注册」这条路走不通；
4. ⚠️ **被授权人的账号事后被删**的话，那一行还在但不生效。授权页上标出来，
   **不自动撤销** —— 同下面那一条。

## 八、两条只标注、不改权限的情况

- 授权人自己后来不再管理这个 ministry 了 → **授权继续有效**，列表上标出来
  （用户拍的板）。它是一条独立的、记了 `granted_by` 的授权，不是他权力的延伸；
  而活动办到一半授权集体失效，比留着更危险；
- 被授权人的账号没了 → 同上，标出来。

## 九、推迟的，以及各自的重启条件

| 事情 | 何时重新考虑 |
|---|---|
| 授权给**一门课的某几讲** | 真的出现「这三讲我不在，请人代一下」时。⚠️ 那不是这张表加一列，是一张挂 `Session` 的表 |
| 第二档权限（比如「只能签到，改不了活动」） | 基金会说得出一个真实的场景时。⚠️ 那是一次要连同 `permissions.py` 的判断一起改的改动，不是在这张表上加一个枚举 |
| 转授 | ⚠️ **大概率永不** —— 见[第三节](#三被授权人拿不到的三样各有各的判断)那一行 |
| 授权给整个**系列** | 真的有人要「这十二场都交给他」时。今天的做法是逐场授权，而十二次点击是一个真实的代价 |
