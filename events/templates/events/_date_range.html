{% comment %} 日期区间：一颗胶囊，点开是双月日历（2026-09-15，用户给了截图）。 🔴 **底下那两个原生日期框有两个身份，两个都要**： ① **没有 JavaScript 时唯一的入口** —— 日历是脚本画的，而筛选是读操作， D24 那条硬规矩管不到它；即便如此，留着这条路的成本是零。 ② **所有人设定单边区间的正经入口**（用户 2026-09-15 定的）：日历上点两下 得到的是一段，而「从九月一号起，不限截止」只有这两个框说得出来。 `EventPeriodForm.description()` 早就支持单边（`from X` / `until Y`）， 所以后端一个字都不用改。 🔴 **用原生 `popover`，不用 Alpine 的 `x-show` 也不用绝对定位的下拉** —— 照 `row_menu.html` 那一套：自带 light-dismiss 和 Esc，渲染在 **top layer**， 祖先的 `overflow` 和 `backdrop-filter` 都够不着它。这张卡在开着日程时是 钉住的、外面还套着会滚的列，绝对定位的下拉在那里会被裁掉。 ⚠️ 没有 JS 时 popover 落在**视口居中**（规范的默认锚定），定位由 app.js 那段补 —— 同 `row_menu.html`，那里第一次踩到并记下了。 ⚠️ 胶囊上的字走 `period.date_chip`：它和 `description()` 共用那三个分支 （两端 / 只有 start / 只有 end），但**格式不同** —— 报表正文要的是 「15 Sep 2026 – 01 Oct 2026」（带年份），这颗胶囊要的是「Sep 15 – Oct 1」。 两处各有各的去处，合并会让其中一个变形。 参数：past_selectable —— 真值则日历里今天之前的日子可点（管理页报表要拉历史）。 {% endcomment %}
